# ADR-0044: Peppol & E-faktura-standarder

## Status
Accepted — 2025-09-11

## Kontext
För att uppfylla lagkrav och kundkrav behöver AccountingAgent stödja e-fakturering via **Peppol**.  
ADR-0029 och ADR-0034 beskriver fakturaflöden, men ett separat beslut behövs om hur standarderna hanteras, valideras och integreras.  
Fokus är att säkerställa kompatibilitet med svenska och europeiska krav (Svefaktura, Peppol BIS Billing 3.0).

## Beslut
- **Standarder**  
  - AccountingAgent implementerar stöd för **Peppol BIS Billing 3.0** som primär standard.  
  - Svenska **Svefaktura** stöds via mappning till Peppol-format.  
  - XML-validering sker vid fakturagenerering med XSD-schema.  

- **Integration**  
  - `PeppolService` ansvarar för att generera Peppol-fakturor.  
  - FortnoxPlugin används för att lagra fakturan, men utskick sker via `PeppolGatewayPlugin`.  
  - Gateway-anslutning sker via certifikat (SMP/SML).  

- **Validering**  
  - Alla Peppol-fakturor valideras innan utskick.  
  - Felaktiga fakturor skickas inte vidare utan loggas och skickas till manuell review.  
  - Valideringsrapporter sparas i `/mnt/nfs/peppol/validation/`.  

- **Fallback**  
  - Om mottagaren inte stöder Peppol skickas fakturan via EasyInvoice (PDF) eller e-post.  
  - Isa markerar tydligt i svaret vilken metod som användes.  

- **WebChat-flöde**  
  - Användare: *“Skicka fakturan till kunden via Peppol”*.  
  - Isa kör direkt → validerar, skickar via gateway, loggar resultat.  
  - Svar: “✅ Faktura #10023 skickad via Peppol. Valideringsrapport sparad.”  

## Konsekvenser
+ Säkerställer efterlevnad av EU-standard för e-fakturering.  
+ Minskar manuell hantering genom validering och automatiska fallback-flöden.  
+ Tydlig spårbarhet via loggar och rapporter.  
- Kräver extra konfiguration av Peppol-certifikat och gateway.  
- Risk för ökade kostnader vid tredjeparts gateway-tjänster.
