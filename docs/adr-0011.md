# ADR-0011: Teststrategi för AccountingAgent

## Status
Accepted — 2025-09-11

## Kontext
Systemet består av Agent, WebChat och ett flertal plugins (Fortnox, DocumentInterpreter, CompanyCheckup, m.fl.).  
Issues och roadmap pekar på behov av enhetliga testregler:
- Alla plugins måste ha tillhörande tester.  
- Nightly tests för regression och stabilitet.  
- Krav att build/test är helt grönt innan deployment.  
- Diskussion om verktyg (FakeItEasy vs Moq).

## Beslut
- **Testframework:** xUnit.  
- **Mocking:** FakeItEasy (föredras framför Moq).  
- **Teststruktur:**  
  - En testklass per produktionsklass (`XyzService ↔ XyzServiceTests`).  
  - Plugins testas separat i respektive `*.Tests`-projekt.  
- **Coverage:**  
  - Alla publika metoder ska ha minst ett test.  
  - Alla plugins måste ha minst smoke-tests för initiering och API-anrop.  
- **Nightly Tests:**  
  - Körs automatiskt via GitHub Actions.  
  - Fokus på integrationstester (Fortnox sandbox, OCR, notifieringar).  
- **CI/CD-regler:**  
  - Inga varningar tillåtna (behandlas som fel).  
  - Grön testsvit krävs för merge till main.  

## Konsekvenser
+ Säkerställer hög kvalitet och minskar regressionsrisk.  
+ Tydlig struktur gör det lättare för nya utvecklare att förstå testkrav.  
+ Nightly tests upptäcker externa API-fel tidigt.  
- Ökar initialt arbetstid då varje klass kräver tester.  
- Kräver mockning av externa API:er för att inte belasta sandbox i onödan.
