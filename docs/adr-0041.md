# ADR-0041: Testing in Production & Nightly Jobs

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent integrerar med externa tjänster (Fortnox, Twilio, BankID, Verified, m.fl.) där API:er och miljöer kan förändras över tid.  
För att undvika driftavbrott behöver systemet automatiskt verifiera funktionaliteten i produktion och i sandbox.  
Issues beskriver behovet av nightly tests, smoke-tests vid deploy och kontinuerlig hälsokontroll.

## Beslut
- **Nightly Jobs**  
  - Körs varje natt via Quartz.  
  - Testar integrationer (Fortnox sandbox, OCR, notifieringar).  
  - Resultat loggas i `JobHistory` och skickas som rapport till systemansvarig.  

- **Testing in Production (TiP)**  
  - Smoke-tests körs vid varje deployment mot produktion.  
  - Exempel: hämta kundlista från Fortnox (read-only), skicka testnotifiering.  
  - Fel i smoke-tests → rollback och notifiering.  

- **Regressionstester**  
  - Automatiskt schema för att köra full testsvit (unit + integration) nattligen.  
  - Jämför resultat mot tidigare körningar för att upptäcka förändringar.  

- **Healthchecks**  
  - Alla tjänster exponerar `/health`-endpoint.  
  - QuartzHealthCheckService övervakar schemaläggning.  
  - Resultat visas i Grafana och skickas som notifiering vid fel.  

- **Observability-integration**  
  - Nightly jobs korreleras med traceId/spanId i OTEL.  
  - Rapporter inkluderar länk till Grafana dashboard för vidare analys.  

## Konsekvenser
+ Tidig upptäckt av API-förändringar eller externa fel.  
+ Ökad driftsäkerhet tack vare automatiserade regressionstester.  
+ Transparens via nattliga rapporter och Grafana dashboards.  
- Kostnader för API-anrop i sandbox.  
- Risk för falsklarm vid tillfälliga nätverksstörningar.
