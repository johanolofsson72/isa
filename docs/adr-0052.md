# ADR-0052: GDPR Export & Användardata (self-service export, glömska, rättigheter)

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent hanterar känsliga person- och företagsdata.  
ADR-0036 definierade minnespolicies och retention.  
För att uppfylla GDPR måste systemet erbjuda användare rätt till insyn, rättelse och radering (glömska), samt möjliggöra export av data kopplad till en användare eller ett kundbolag.

## Beslut
- **Self-service export**  
  - Användare kan i WebChat be Isa: *“Exportera all min data”*.  
  - Export sker i JSON-format (primärt) eller CSV/Excel (sekundärt).  
  - Exportpaket lagras i `/mnt/nfs/exports/gdpr/<userId>/` och är tillgängligt via länk i WebChat.  

- **Glömska (Right to be forgotten)**  
  - Användare kan be Isa: *“Glöm mig”* eller *“Glöm vad jag sa igår”*.  
  - Korttidsminne (SQLite) rensas omedelbart.  
  - Långtidsminne (Postgres) markeras som “deleted” och raderas permanent vid nästa retention-jobb.  
  - Bokföringsdata som är lagkrav (7 års retention) undantas från radering, men anonymiseras där det är möjligt.  

- **Rättelser**  
  - Användare kan korrigera metadata via WebChat (ex. namn, e-post).  
  - Historik sparas i AuditLogService för transparens.  

- **Audit & spårbarhet**  
  - Alla GDPR-förfrågningar loggas i `GDPRRequestLog`.  
  - Varje export eller radering får ett `traceId` för revision.  

- **Administratörskontroller**  
  - Systemansvarig kan initiera export/radering via AdminUI.  
  - Endast systemansvarig kan överskrida retention (t.ex. om kund begär tidigare radering).  

## Konsekvenser
+ Uppfyller GDPR-krav på insyn, rättelse och glömska.  
+ Transparens och förtroende stärks hos kunder.  
+ Automatisering minskar manuellt arbete för systemansvarig.  
- Mer komplexitet i memory management (delvis anonymisering).  
- Risk för konflikter mellan GDPR och Bokföringslagen → kräver tydliga regler.
