# ADR-0036: Minnespolicies & GDPR (glömska, retention, persondata)

## Status
Accepted — 2025-09-11

## Kontext
ADR-0006 beskrev Isa’s minnesarkitektur (korttids- och långtidsminne).  
För att följa GDPR och Bokföringslagen krävs tydliga policies kring hur minne och persondata hanteras.  
Issues har påpekat att Isa ibland blandar ihop användare och hemligheter, vilket gör datasäkerhet kritisk.

## Beslut
- **Korttidsminne (SQLite)**  
  - Lagrar endast konversationer från pågående session.  
  - Rensas automatiskt efter 24 timmar eller vid sessionens slut.  

- **Långtidsminne (Postgres + pgvector)**  
  - Sparar endast information som är relevant för redovisning eller återkommande arbetsflöden.  
  - Varje post taggas med `userId`, `role` och `retentionPolicy`.  
  - Standard retention: 7 år (enligt Bokföringslagen).  

- **Persondata**  
  - Användares privata konversationer flaggas som “sensitive”.  
  - Endast systemansvarig har rätt att radera persondata manuellt.  
  - Isa kan utföra “glömska” på begäran: *“Glöm vad jag sa igår”*.  

- **Audit & Spårbarhet**  
  - Alla memory writes loggas i `AuditLogService`.  
  - `traceId` kopplar minneshändelser till användarsessioner.  
  - Raderingar loggas med tidpunkt och användar-ID.  

- **Export**  
  - Användare kan exportera all sparad data kopplad till sin identitet.  
  - Export sker i JSON-format via WebChat eller AdminUI.  

## Konsekvenser
+ Uppfyller GDPR-krav på rätt till insyn och radering.  
+ Säkerställer att bokföringsdata sparas i 7 år enligt lag.  
+ Användare får kontroll över sina data.  
- Mer komplex logik i minnessystemet.  
- Kräver dedikerade rutiner för backup och radering.
