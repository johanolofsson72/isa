# ADR-0054: Developer Experience & Augment Code-integration

## Status
Accepted — 2025-09-11

## Kontext
Projektet använder **Augment Code (Auggi CLI)** och andra AI-assistenter för att generera och refaktorera kod.  
För att undvika rörig kod och säkerställa enhetlighet behövs tydliga regler för **developer experience (DX)** och hur AI får användas.  
`.augment`-katalogen (system-prompt, rules, state) fungerar som styrsystem för AI och utvecklare.

## Beslut
- **Projektstruktur & Regler**  
  - Feature-baserad struktur är obligatorisk (en mapp per domän: Customers, Invoices, Reports, etc.).  
  - AI får inte lägga filer i roten, utan måste följa strukturen.  
  - Testprojekt skapas parallellt med varje nytt featureprojekt.  

- **.augment-katalog**  
  - `system-prompt.md`: definierar AI:s roll (korrekthet > bekvämlighet).  
  - `rules.md`: kod- och testregler (inga varningar, FakeItEasy, idempotenta scripts).  
  - `state.json`: återstartssäkert minne för pågående utvecklingsstatus.  

- **AI-användning**  
  - AI-assistenter måste alltid uppdatera:  
    - `docs/INTEGRATION.md` vid nya integrationer.  
    - `docs/INSTRUCTIONS.md` vid nya arbetssätt.  
    - `docs/adr-xxxx.md` vid arkitekturbeslut.  
  - AI får aldrig ta bort volymer, Docker-data eller produktionsfiler utan manuell bekräftelse.  

- **Testkrav**  
  - Alla AI-genererade klasser måste ha minst ett motsvarande test.  
  - Testlayout valideras med `validate-test-layout.sh`.  
  - Nightly regressionstester körs för att fånga AI-genererad kod som bryter reglerna.  

- **Developer Experience (DX)**  
  - GitHub Actions-pipeline validerar regler (lint, build, test).  
  - AI-förslag granskas manuellt innan merge.  
  - PRD/ADR hålls alltid uppdaterade i takt med utvecklingen.  

## Konsekvenser
+ Strikt men förutsägbar utvecklingsprocess även med AI.  
+ `.augment` fungerar som “rails” för både mänskliga och AI-utvecklare.  
+ Mindre risk för teknisk skuld från ogenomtänkta AI-förslag.  
- Kräver disciplin att alltid uppdatera dokument och ADR.  
- Kan kännas byråkratiskt för snabba prototyper.
