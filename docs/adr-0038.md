# ADR-0038: Arkivering & Revisionsspår

## Status
Accepted — 2025-09-11

## Kontext
Bokföringslagen kräver att allt underlag sparas i minst 7 år.  
Systemet måste säkerställa att dokument, fakturor, rapporter och bilagor arkiveras på ett revisionssäkert sätt.  
Issues beskriver behovet av checksummor, versionshantering och koppling mellan verifikationer och bilagor.

## Beslut
- **Arkivering av bilagor**  
  - Alla dokument (kvitton, leverantörsfakturor, kundfakturor, rapporter) sparas i `/mnt/nfs/archives/`.  
  - Metadata registreras i Postgres (`ArchiveRecord`) med fält: `fileId`, `checksum`, `verifikationId`.  
  - Bilagor laddas även upp till Fortnox för dubbel spårbarhet.  

- **Checksummor & integritet**  
  - Varje fil hashas (SHA-256) vid uppladdning.  
  - Hash lagras i `ArchiveRecord` och används för att verifiera oförändrad fil.  
  - Periodiska integritetskontroller körs via `ArchiveIntegrityService`.  

- **Versionshantering av rapporter**  
  - Alla rapporter (P&L, balans, moms, årsrapport) versioneras med timestamp.  
  - Exporterade filer innehåller metadata i filnamn: `Report_<type>_<YYYYMMDD>_<traceId>.pdf`.  

- **Audit-logg**  
  - Alla arkiveringshändelser loggas via `AuditLogService`.  
  - Loggar innehåller `userId`, `role`, `action`, `traceId`.  

- **Retention**  
  - Standard: 7 år.  
  - Äldre filer flyttas till kallt lagringsutrymme (`/mnt/nfs/cold-archive/`).  
  - Radering endast tillåten efter lagstadgad retention och kräver admin-godkännande.  

## Konsekvenser
+ Uppfyller lagkrav på bokföringsunderlag.  
+ Säkerställer att alla filer är revisionsbara och verifierbara.  
+ Integritetskontroller skyddar mot korruption eller manipulation.  
- Ökad lagringskostnad över tid.  
- Kräver rutiner för backup och kallarkivering.
