# ADR-0026: Integration med Fortnox Sandbox & Prod

## Status
Accepted — 2025-09-11

## Kontext
Fortnox är det första ERP-systemet som AccountingAgent integreras mot.  
För att säkra utveckling och drift krävs tydlig separation mellan **sandbox** och **produktion** samt regler för hantering av tokens och bilagor.  
Issues visar behov av enhetliga rutiner för testning, idempotens och bilagelagring.

## Beslut
- **API-åtkomst**  
  - OAuth2 används för autentisering.  
  - Sandbox och prod har separata klient-ID/secret.  
  - Tokens lagras i `fortnox-access-token.json` (endast lokalt eller via KeyVault).  

- **Miljöer**  
  - **Sandbox** används för utveckling och integrationstester.  
  - **Prod** används endast för skarpa flöden.  
  - Alla nya features måste verifieras i sandbox innan prod-release.  

- **Bilagor**  
  - Bilagor laddas alltid upp till Fortnox tillsammans med verifikationen.  
  - Filer sparas även lokalt i `/mnt/nfs/uploads/` för spårbarhet.  

- **Idempotens**  
  - Alla POST-anrop skickas med `externalIdempotencyKey`.  
  - Automatisk retry/backoff vid felkoder (429, 500).  

- **Teststrategi**  
  - **Unit-tester** körs med mockat Fortnox-API.  
  - **Integrationstester** körs mot sandbox (nightly).  
  - **Smoke-tests** körs vid varje deploy mot prod (hämtar data utan att skriva).  

## Konsekvenser
+ Ger säker utveckling och minskar risken för fel i skarp miljö.  
+ Full spårbarhet på bilagor och verifikationer.  
+ Sandbox gör att utveckling kan ske utan att påverka riktiga kunder.  
- Kräver underhåll av dubbla uppsättningar API-nycklar och secrets.  
- Sandbox är ibland begränsad jämfört med produktion (kan ge felaktig testbild).
