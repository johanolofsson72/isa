# ADR-0031: Mail- och dokumentingestion (Gmail, Google Drive, Dropbox)

## Status
Accepted — 2025-09-11

## Kontext
För att automatisera bokföringsflöden behöver AccountingAgent kunna hämta underlag från flera källor.  
Issues och roadmap beskriver behovet av att läsa in dokument från Gmail, Google Drive och Dropbox samt att tolka bilagor automatiskt.

## Beslut
- **Gmail**  
  - `MailPlugin` används för att läsa inkommande mejl från definierade adresser (ex. kvitton@…).  
  - Bilagor extraheras och skickas vidare till `DocumentInterpreterPlugin`.  
  - Metadata loggas i Postgres (avsändare, datum, ärende-ID).  

- **Google Drive**  
  - `GoogleWorkspacePlugin` används för att hämta filer från specifika mappar.  
  - Filer kopieras till `/mnt/nfs/uploads/` för tolkning och arkivering.  
  - OAuth2 används för autentisering.  

- **Dropbox**  
  - `DropboxPlugin` används för integration med kunders Dropbox-mappar.  
  - Filhändelser (upload/update/delete) triggar ingestion-flöden.  

- **Pipeline**  
  - Alla importer går genom `DocumentInterpreterService`.  
  - Klassificering sker (kvitto, leverantörsfaktura, kundfaktura).  
  - Resultat skickas till `FortnoxPlugin` för bokföring.  
  - Bilagan länkas till verifikationen.  

- **Felhantering**  
  - Misslyckade tolkningar skickas till manuell review i WebChat.  
  - Idempotens säkerställs med `externalIdempotencyKey` per dokument.  

## Konsekvenser
+ Automatiserad insamling av underlag från vanliga källor.  
+ Minskar manuellt arbete för ekonomiansvariga.  
+ Standardiserad pipeline ger spårbarhet.  
- Kräver hantering av OAuth2 för flera externa tjänster.  
- Risk för dubbletter → måste hanteras via idempotensnycklar.
