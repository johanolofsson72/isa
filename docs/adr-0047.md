# ADR-0047: Standardvärden & Auto-resolve

## Status
Accepted — 2025-09-11

## Kontext
User cases visar att ekonomiansvariga vill arbeta snabbt i Isa utan att alltid behöva specificera alla detaljer.  
Exempel: *“Fakturera 10 timmar till RFLX AB”* — här kan Isa behöva fylla i artikel, timpris och betalvillkor.  
För att minska friktion krävs regler för **standardvärden** och hantering av **osäkra matchningar**.

## Beslut
- **Standardvärden (defaults)**  
  - Artikel: `Systemutveckling` (eller senaste använda artikel).  
  - Timpris: senaste använda timpris för kunden, annars global standard (ex. 1 200 SEK/h).  
  - Betalvillkor: standard 30 dagar netto.  
  - Moms: standard 25 % om inte kundpost säger annat.  
  - Konto: baseras på BAS-kontoplanens default för fakturor/kostnader.  

- **Auto-resolve**  
  - Vid flera kundmatchningar (ex. “RFLX” finns i flera varianter) väljer Isa **bästa match** baserat på org.nr, senaste användning eller kundstatus.  
  - Isa **informerar**: *“Jag valde RFLX AB (org.nr 556123-4567). Vill du korrigera?”*  
  - Status markeras med 🟡 när osäkerhet föreligger.  

- **Bekräftelse i dialog**  
  - Isa säger alltid vilka standardvärden som användes.  
  - Ex: *“Jag kommer skapa en faktura på 10 timmar á 1 200 SEK (Systemutveckling, betalvillkor 30 dagar) till RFLX AB. Stämmer det?”*  

- **Konfiguration**  
  - Standardvärden kan administreras av systemansvarig i `defaults.json`.  
  - Ekonomiansvariga kan ändra defaults per kund via WebChat-kommandon (ex. “Sätt standardtimpris för RFLX AB till 1 400 SEK”).  

## Konsekvenser
+ Snabbare arbetsflöden för vanliga scenarier.  
+ Mindre risk för fel när Isa alltid berättar vilka defaults som används.  
+ Auto-resolve gör att uppdrag kan fortsätta även vid tvetydighet.  
- Risk att felaktiga defaults används om de inte underhålls.  
- Kräver logik för att avgöra “bästa match” vid osäkerhet.
