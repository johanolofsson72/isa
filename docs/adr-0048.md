# ADR-0048: Klientportal & E-sign-workflows

## Status
Accepted — 2025-09-11

## Kontext
ADR-0021 beskrev en klientportal för kunder (fildelning, status, e-signering).  
ADR-0007 definierade BankID och PAdES som signeringsstandard.  
Det behövs en fördjupning kring hur klientportalen ska hantera **e-sign-workflows** så att kunder och byråer kan arbeta helt digitalt med avtal och ekonomiska underlag.

## Beslut
- **Klientportal-plugin**  
  - Portalen byggs som separat frontend (Blazor/React) och exponeras via ClientPortalPlugin.  
  - Kundinloggning sker med BankID eller OAuth2 (Microsoft/Google).  
  - Portalen visar status för: fakturor, uppladdade kvitton, årsrapporter, pågående e-signeringar.

- **E-sign-workflows**  
  - Workflow: [Dokument → Initiera signering → BankID → PAdES genereras → Arkiveras].  
  - Signeringsstatus uppdateras i realtid i klientportalen.  
  - När alla parter signerat → dokumentet markeras “juridiskt bindande” och länkas till Fortnox-verifikation eller kundpost.  

- **Integration med WebChat (Isa)**  
  - Ekonomiansvarig kan trigga signering via WebChat:  
    - *“Be kunden signera detta avtal”*.  
  - Isa skickar dokumentet till klientportalen och initierar signeringsprocessen.  
  - Isa återkopplar när signeringen är klar.  

- **Arkivering & revisionsspår**  
  - Alla signerade dokument sparas i `/mnt/nfs/archives/esign/`.  
  - Metadata (signeringsparter, tid, BankID-hash, checksumma) sparas i Postgres.  
  - AuditLogService loggar hela processen.  

- **Fallback**  
  - Om BankID eller tredjepartsintegration (ex. Verified) fallerar → Isa föreslår manuell signering (PDF via e-post).  

## Konsekvenser
+ Kunder kan själva ladda upp, signera och följa ärenden digitalt.  
+ Full spårbarhet och juridisk giltighet genom PAdES + BankID.  
+ WebChat och klientportal arbetar sömlöst ihop.  
- Extra driftkostnad för tredjepartsintegrationer (Verified, BankID).  
- Kräver UI både i WebChat och klientportal.
