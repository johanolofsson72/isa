# ADR-0017: Observability & Monitoring

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent körs i Docker Swarm (demo-cluster) och består av flera komponenter: Agent, WebChat, Plugins, databaser.  
För att säkerställa driftsäkerhet behövs komplett observability: loggar, metrics och spårning.  
Issues och roadmap nämner OpenTelemetry, Netdata, Prometheus och Grafana.

## Beslut
- **OpenTelemetry (OTEL)**  
  - Alla tjänster instrumenteras med OTEL för spårning (`traceId`, `spanId`).  
  - Loggar skickas i JSON-format med timestamp, nivå, event, traceId.  
  - Export till Prometheus och Grafana dashboards.  

- **Netdata**  
  - Körs globalt på alla noder för realtidsövervakning.  
  - Data skickas även till Netdata Cloud för central vy.  

- **Prometheus + Grafana**  
  - Prometheus samlar metrics från Agent, WebChat och plugins.  
  - Grafana visualiserar dashboards (hälsa, svarstider, CPU, minne).  
  - Larm skickas via Mail/SMS/Slack vid avvikelse.  

- **Healthchecks**  
  - Varje service implementerar `/health`-endpoint (200 OK vid fungerande status).  
  - QuartzHealthCheckService övervakar schemaläggning.  
  - McpWebSocketServer övervakas för anslutningsstatus.  

- **Nightly Checks**  
  - Extra testjobb körs varje natt för att verifiera att alla endpoints och arbetsflöden fungerar.  
  - Resultat sparas i `JobHistory` och skickas som rapport via e-post.  

## Konsekvenser
+ Förutsägbara driftsproblem (tidig varning via metrics och larm).  
+ Full spårbarhet i alla arbetsflöden (traceId/spårning).  
+ Grafisk översikt (Grafana) för både utvecklare och ekonomiavdelning.  
- Kräver underhåll av Prometheus/Grafana-stacken.  
- Kostnad i prestanda (OTEL-tracing kan öka CPU-belastning).
