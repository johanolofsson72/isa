# ADR-0006: Minnesarkitektur för Isa (korttids- och långtidsminne)

## Status
Accepted — 2025-09-11

## Kontext
Issues #101 (*“Minnet är kort hos Isa”*) och #79 (*“Isa har fått hjärna och minne men har problem med att skilja på personer och hemligheter”*) visar att nuvarande minnessystem inte räcker för produktion.  
Isa behöver:
- **Korttidsminne** för pågående konversationer i WebChat.  
- **Långtidsminne** för historik, dokument och tidigare beslut.  
- Möjlighet att skilja på **personligt innehåll** (per användare) och **globalt kontext** (system/bokföring).  

## Beslut
- **Korttidsminne** lagras i SQLite (`memory.db`) med automatisk rensning via `MemoryMaintenanceService`.  
- **Långtidsminne** lagras i Postgres med **pgvector** för semantiska sökningar.  
- **Hybridmodell**:  
  - WebChat använder korttidsminne för pågående session.  
  - Långtidsminne används för att återkalla kontext, tidigare underlag och referenser.  
- **Säkerhet**:  
  - Personliga data flaggas med metadata (`userId`).  
  - Globala data (pluginbeskrivningar, systemregler, bokföringsmallar) delas mellan alla användare.  
- **Services**:  
  - `ProductionMemoryService` → uthålligt långtidsminne.  
  - `IntelligentMemoryExtractor` → avgör vad som ska sparas.  
  - `MemoryQueryService` → API för WebChat att söka i historik.  

## Konsekvenser
+ Användare kan be Isa “kom ihåg vad jag sa igår” och få korrekt svar.  
+ Systemet kan växa utan att konversationer blir för tunga (korttidsminne rensas).  
+ Möjlighet att bygga rapporter baserade på tidigare konversationer och handlingar.  
- Ökad komplexitet: kräver både relationsdatabas (Postgres) och vektordatabas (pgvector).  
- Kräver rutiner för “glömska” för att följa GDPR.
