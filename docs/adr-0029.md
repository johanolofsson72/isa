# ADR-0029: E-handel & Fakturaflöden (EasyInvoice, Peppol, PDF-export)

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent behöver hantera flera olika fakturaflöden för att stödja både bokföringsbyråer och kunders e-handel.  
Roadmap och issues pekar på integration med **EasyInvoice**, stöd för **Peppol**-format, samt **PDF-export** som fallback.  
Fas 2 omfattar särskilt att sortera fakturor i olika flöden baserat på kund och leverantör.

## Beslut
- **Fakturaflöden**  
  - **EasyInvoice**: PDF-fakturor skickas via EasyInvoice API.  
  - **Peppol**: Elektroniska fakturor skickas via Peppol när mottagaren stöder det.  
  - **Fallback**: PDF-fakturor via e-post när inget av ovan är möjligt.  
  - Flödet styrs via `InvoiceFlowService` som klassificerar fakturor.  

- **Export**  
  - Alla fakturor sparas i Fortnox.  
  - PDF-version genereras med Syncfusion (eller motsv.).  
  - Arkiveras i `/mnt/nfs/invoices/` tillsammans med metadata.  

- **Arbetsflöden**  
  - Isa kan i WebChat initiera:  
    - *“Skicka denna faktura via EasyInvoice”*  
    - *“Exportera som Peppol”*  
    - *“Generera PDF och maila kund”*  
  - WorkflowScheduler hanterar schemalagda fakturaexporter.  

- **Testning**  
  - EasyInvoice integration testas i sandbox-miljö.  
  - Peppol valideras med testfiler.  
  - PDF-export testas automatiskt i unit-tests.  

## Konsekvenser
+ Stöd för flera olika fakturaflöden ökar flexibiliteten.  
+ EasyInvoice ger snabb time-to-market där Peppol inte används.  
+ Fallback till PDF säkerställer att alla kunder kan faktureras.  
- Mer komplex logik i `InvoiceFlowService`.  
- Risk för dubbletter om idempotens inte implementeras korrekt.
