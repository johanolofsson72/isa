# ADR-0018: Plugin Lifecycle & Discovery

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent bygger på en **plugin-arkitektur** (MCP).  
Plugins ska kunna upptäckas dynamiskt, aktiveras/deaktiveras per kund, och versioneras utan att kärnkoden ändras.  
Issues och implementationer (`DynamicPluginDiscoveryService`, `DatabaseAwarePluginDiscoveryService`, `JsonPluginGenerator`) visar hur detta har påbörjats.

## Beslut
- **Discovery Services**  
  - `DynamicPluginDiscoveryService`: söker plugins dynamiskt i källkoden.  
  - `DatabaseAwarePluginDiscoveryService`: läser pluginmetadata från databasen.  
  - `HybridPluginDiscoveryService`: kombinerar statisk + dynamisk upptäckt.  

- **Plugin Lifecycle**  
  - **Registrering**: via `PluginFactory` i respektive pluginprojekt.  
  - **Metadata**: lagras i Postgres (`PluginMetadata`-tabell).  
  - **Generering**: `JsonPluginGenerator` exporterar plugin-definitioner för WebChat och MCP-klienter.  
  - **Tillstånd**: `PluginState` används för att aktivera/deaktivera plugins per kund/miljö.  

- **Versionering**  
  - Plugins versioneras separat och kan deployas utan att Agent behöver byggas om.  
  - Metadata innehåller version + kompatibilitet.  

- **WebChat-integration**  
  - Plugin Management UI → lista, aktivera/deaktivera plugins.  
  - Stöd för att per kund välja vilka plugins som är aktiva.  

## Konsekvenser
+ Lätt att lägga till nya funktioner utan att röra Agent-koden.  
+ Plugins kan anpassas per kund, vilket ger flexibilitet.  
+ WebChat gör det tydligt vilka plugins som är aktiva.  
- Ökad komplexitet (många discovery-lager).  
- Kräver testfall för att verifiera att rätt plugins laddas i rätt miljö.
