# ADR-0023: Deploymentmiljö & Infrastruktur

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent driftas i Linuxbaserade Docker Swarm-kluster (demo-cluster).  
Systemet har flera krav: idempotenta deploy-scripts, persistent lagring, backup, och lokalt container registry.  
Issues och tidigare setup-dokument beskriver att Portainer, Netdata och Nginx Proxy Manager körs på manager-noden, medan plugins och databaser körs i Swarm.

## Beslut
- **Kluster**  
  - 1 manager + flera worker-noder.  
  - Spot-instanser används för kostnadseffektiv drift.  
  - Alla stackar ska kunna flyttas automatiskt vid nodförlust.

- **Registry**  
  - Lokalt container registry (`registry.example.com:5000`).  
  - CI/CD pushar images dit innan deploy.  
  - Garbage collection via `clean-registry.sh`.

- **Lagring**  
  - `/mnt/nfs` på manager-noden för WordPress/wwwroot, uploads och backups.  
  - Longhorn planeras för framtida persistens per stack.  

- **Backup**  
  - Daglig backup av databaser (Postgres, SQLite) och filsystem (`/mnt/nfs`).  
  - Retention: 7 dagar.  
  - Backuper sparas i AFS (Azure File Share) eller motsvarande.  

- **Scripts**  
  - Alla deploy-scripts (`demo-step*.sh`) ska vara **idempotenta**.  
  - Scripts verifierar installation och skickar e-postrapport via Mailjet.  
  - Resultat sparas i `*-result.txt` på manager-noden.  

- **Observability**  
  - Netdata körs globalt på alla noder.  
  - Falco används för runtime-säkerhet.  
  - Prometheus/Grafana för metrics.  

## Konsekvenser
+ Stabil och repeterbar driftmiljö.  
+ Idempotenta scripts gör att deployment kan köras om utan risk.  
+ Backup/restore ger hög återställningsförmåga.  
- Mer komplex setup än en enkel Docker Compose.  
- Swarm kräver manuell hantering vid större nätverksproblem.
