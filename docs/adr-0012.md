# ADR-0012: CI/CD & Deployment-strategi

## Status
Accepted — 2025-09-11

## Kontext
Projektet driftas i Docker Swarm (demo-cluster).  
Images byggs och pushas till ett **lokalt container registry** (`registry.example.com:5000`).  
Issues och guider (`CI-CD_AUGMENT.md`, deploy-scripts) beskriver att pipeline ska vara helt automatiserad och 100 % stabil.  

## Beslut
- **CI/CD** körs i GitHub Actions.  
- **Pipelineflöde**:  
  1. **Bygg & testa** (`dotnet build` + `dotnet test`).  
  2. **Tagga image** baserat på datum/tid.  
  3. **Push** till lokalt registry `registry.example.com:5000/<project>/<service>:<tag>`.  
  4. **Deploy** till Docker Swarm med stack- eller service-update.  
- **Regler**:  
  - Alla varningar = fel (måste åtgärdas).  
  - Alla projekt kompileras.  
  - Testsvit måste vara grön.  
- **Miljöer**:  
  - `dev` (lokal maskin).  
  - `test` (sandbox mot Fortnox, OCR, notifieringar).  
  - `prod` (Swarm i demo-cluster).  
- **Hemligheter**:  
  - Hanteras via GitHub Secrets + env-filer.  
  - Inga secrets i repo.  
- **Observability**:  
  - Healthcheck endpoints.  
  - Prometheus metrics.  
  - Grafana dashboards.  
  - E-postnotifiering via Mailjet vid misslyckad deploy.  

## Konsekvenser
+ En stabil och repeterbar deployment-pipeline.  
+ Lokal registry minskar beroende av externa tjänster och sparar kostnader.  
+ CI/CD-regler säkerställer kvalitet innan drift.  
- Kräver underhåll av egen registry.  
- Swarm behöver idempotenta deploy-scripts (måste tåla att köras flera gånger).
