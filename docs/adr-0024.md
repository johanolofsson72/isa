# ADR-0024: AI-integration & Promptstyrning

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent använder AI-modeller (OpenAI, Azure) för att tolka dokument, driva dialogflöden och assistera utvecklare via Augment Code.  
För att säkerställa kvalitet och konsekvens behövs tydlig styrning av **system-promptar**, **regler** och dokumentation i `.augment/`.

## Beslut
- **System-prompt**  
  - Definieras i `.augment/system-prompt.md`.  
  - Strikt och saklig, korrekthet före bekvämlighet.  
  - AI ska motsäga felaktigheter och alltid motivera beslut.  

- **Regler**  
  - Ligger i `.augment/rules.md`.  
  - Inga varningar tillåtna vid build/test.  
  - FakeItEasy framför Moq i tester.  
  - All arkitektur dokumenteras i `docs/adr-xxxx.md`.  
  - Cache-busting vid statiska filer (CSS/JS/img).  

- **AI State**  
  - `.augment/state.json` används för återstartssäker status.  
  - Innehåller pågående tasks, noteringar och projektets nuvarande läge.  

- **Koppling till dokumentation**  
  - Alla ändringar i integrationer → `docs/INTEGRATION.md`.  
  - Alla nya arbetssätt → `docs/INSTRUCTIONS.md`.  
  - Alla beslut → `docs/adr-xxxx.md`.  

- **Användning i utveckling**  
  - AI-assistenter (t.ex. Copilot, Augment Code, Isa själv) använder `.augment/` som kontext.  
  - AI får inte generera tester/dokument direkt i roten → måste följa feature-struktur.  

## Konsekvenser
+ Konsistent AI-beteende i utveckling och drift.  
+ Lättare för utvecklare att förstå projektets regler.  
+ Undviker "drift" i AI-beslut genom strikt dokumentation.  
- Kräver disciplin att alltid uppdatera `.augment` och `docs/`.  
- Kan kännas begränsande för utvecklare som är ovana vid strikt styrning.  

## Relaterade Filer
- `.augment/system-prompt.md`  
- `.augment/rules.md`  
- `docs/INSTRUCTIONS.md`  
- `docs/INTEGRATION.md`  
- `docs/adr-0001.md` (dokumentstruktur)
