# ADR-0053: Plugin Marketplace & Distribution

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent bygger på en plugin-arkitektur (MCP).  
För att underlätta återanvändning och distribution av plugins behövs ett strukturerat sätt att paketera, versionera och distribuera dem.  
Detta möjliggör ett **Marketplace**-liknande upplägg där bokföringsbyråer kan aktivera de plugins de behöver.

## Beslut
- **Paketering**  
  - Varje plugin distribueras som ett eget NuGet/Docker-paket.  
  - Paketen innehåller binärer, metadata (`plugin.json`) och README.md.  
  - PluginFactory laddar in plugins dynamiskt vid uppstart.  

- **Versionering**  
  - Plugins versioneras separat från kärnprojektet.  
  - SemVer används: MAJOR.MINOR.PATCH.  
  - Metadata (`plugin.json`) innehåller version, kompatibilitet med AccountingAgent och dependencies.  

- **Marketplace**  
  - En intern Plugin Marketplace byggs (API + UI).  
  - Ekonomiansvariga kan i WebChat eller AdminUI se tillgängliga plugins, läsa beskrivningar och aktivera dem.  
  - Marketplace hämtar plugin-lista från ett registry (`plugins.json` i GitHub/Azure Storage).  

- **Onboarding**  
  - Nya plugins kan registreras via `DynamicPluginDiscoveryService`.  
  - Systemansvariga kan ladda upp plugins manuellt via AdminUI.  
  - WebChat får kommandon som *“Aktivera FortnoxPlugin”*.  

- **Säkerhet**  
  - Alla plugins signeras (SHA-256 checksumma).  
  - Endast signerade plugins kan laddas.  
  - AuditLogService loggar alla plugin-ändringar.  

## Konsekvenser
+ Gör det enkelt för byråer att välja och aktivera rätt funktionalitet.  
+ Plugins kan utvecklas och uppdateras oberoende av kärnprojektet.  
+ Marketplace ger en professionell upplevelse likt Fortnox “tilläggsappar”.  
- Kräver extra drift (registry/marketplace-API).  
- Risk för fragmentering om pluginversioner inte underhålls.
