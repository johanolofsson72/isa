# ADR-0050: Multi-cloud & Hybrid Deployment (Swarm, Azure ACA, fallback)

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent driftas idag i Docker Swarm (demo-cluster).  
Roadmap och infrastruktur-diskussioner pekar på behovet av en hybridmodell där vissa delar även kan köras i **Azure ACA (App Container Apps)** eller annan molnmiljö.  
Syftet är att kombinera **kostnadseffektivitet** (Swarm on-prem/spot) med **skalbarhet och tillgänglighet** (Azure).

## Beslut
- **Primär drift**  
  - Docker Swarm på egna Linux-servrar (spot-instanser).  
  - Alla core-tjänster (Agent, WebChat, plugins, DB) körs i Swarm.  

- **Hybriddrift**  
  - Azure ACA används för vissa system som kräver hög tillgänglighet eller integration med Azure-tjänster:  
    - E-signering (BankID, Verified).  
    - AI-analys (ML-modeller, Azure OpenAI).  
    - Backup-hantering.  

- **Fallback-scenario**  
  - Om Swarm-kluster är nere → kritiska tjänster kan köras i Azure ACA.  
  - Backups lagras i Azure File Share och kan mountas både i Swarm och ACA.  

- **CI/CD**  
  - Samma GitHub Actions pipeline kan deploya till Swarm eller ACA.  
  - Miljö väljs via konfiguration (`deploy-env: swarm|aca`).  

- **Observability**  
  - OTEL, Prometheus och Grafana samlar metrics från båda miljöer.  
  - Central dashboard visar status för både Swarm och ACA.  

## Konsekvenser
+ Högre resiliens genom hybrid deployment.  
+ Flexibilitet att köra vissa tjänster i moln vid behov.  
+ Möjlighet att optimera kostnader (Swarm för bulk, ACA för kritiska).  
- Mer komplex drift (två miljöer att hantera).  
- Kräver tydliga regler för vilken tjänst som kör var.
