# ADR-0035: Leverantörsfakturaflöden (uppladdning, tolkning, bokföring i Fortnox)

## Status
Accepted — 2025-09-11

## Kontext
User Case C (leverantörsfaktura) och issues kring DocumentInterpreterPlugin visar behov av en standardiserad process för hantering av leverantörsfakturor.  
Flödet omfattar filuppladdning, dokumenttolkning, bokföring i Fortnox och spårbarhet via bilagor.

## Beslut
- **Filuppladdning**  
  - Användaren laddar upp fakturan via WebChat.  
  - Filen lagras i `/mnt/nfs/uploads/` och registreras i Postgres (`FileRecord`).  

- **Dokumenttolkning**  
  - `DocumentInterpreterPlugin` tolkar dokumentet (leverantör, datum, belopp, moms, förfallodatum).  
  - OCR via Azure Document Intelligence eller fallback till Tesseract.  
  - Resultatet struktureras i `FinancialDocuments`-modell.  

- **Bokföring**  
  - `FortnoxPlugin` bokför fakturan som verifikation.  
  - Bilagan laddas upp och kopplas till verifikationen i Fortnox.  
  - Idempotensnyckel används för att undvika dubbelregistrering.  

- **Arbetsflöde i WebChat**  
  1. Användare: *“Bokför denna leverantörsfaktura jag laddat upp”*.  
  2. Isa bekräftar och tolkar dokumentet.  
  3. Isa bokför fakturan i Fortnox.  
  4. Isa återkopplar: *“Fakturan är bokförd, vad vill du att jag gör nu?”*.  

- **Felhantering**  
  - Om OCR misslyckas skickas dokumentet till manuell review i WebChat.  
  - Misslyckade bokföringar skickas till DLQ.  

## Konsekvenser
+ Automatiserad hantering av leverantörsfakturor minskar manuellt arbete.  
+ Full spårbarhet mellan underlag, verifikation och bilaga.  
+ Användarvänligt via dialogdrivet arbetsflöde i WebChat.  
- OCR kan ha varierande kvalitet beroende på fakturamall.  
- Kräver fallback och manuella rutiner vid fel.
