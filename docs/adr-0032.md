# ADR-0032: Notifieringspolicy & Multi-channel Failover

## Status
Accepted — 2025-09-11

## Kontext
Isa ska kunna skicka notifieringar via flera olika kanaler (SMS, e-post, Slack, WhatsApp, Teams).  
ADR-0014 definierade arkitekturen för notifieringar och plugins.  
Det behövs en tydlig policy för **failover** när en kanal inte fungerar samt regler för prioritering mellan kanaler.

## Beslut
- **Primärkanal per användare**  
  - Varje användare kan konfigurera sin primära kanal i WebChat (ex. SMS eller e-post).  
  - NotificationService använder denna kanal i första hand.  

- **Failover**  
  - Om primärkanal misslyckas efter retries → försök med sekundär kanal.  
  - Sekundär kanal konfigureras per användare (ex. Slack eller WhatsApp).  
  - Alla försök loggas i `NotificationLog`.  

- **Multi-channel broadcast**  
  - För kritiska notifieringar (t.ex. driftstörningar, misslyckade deploys) skickas utskick till flera kanaler samtidigt.  
  - Policy definieras i `NotificationPolicy.json`.  

- **Arbetsflöden**  
  - WorkflowScheduler kan trigga påminnelser via flera kanaler (ex. “Skicka fakturapåminnelse via SMS, fallback e-post”).  
  - Isa kan i dialog bekräfta kanalval: *“Vill du att jag skickar som SMS eller e-post?”*.  

- **Felhantering**  
  - Retries med exponential backoff (max 5 försök).  
  - Permanent fel → DLQ (Dead-letter Queue) för manuell hantering.  

## Konsekvenser
+ Högre leveranssäkerhet på notifieringar.  
+ Användare kan anpassa notifieringspolicy efter behov.  
+ Kritiska meddelanden når mottagaren även vid driftstörningar i en kanal.  
- Mer komplex logik i NotificationService.  
- Risk för dubbletter om failover inte hanteras korrekt.
