# ADR-0040: Backup & Restore-strategi (databaser, filer, rapporter)

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent hanterar både bokföringsdata, filer (bilagor, fakturor, rapporter) och minnesdatabaser.  
För att säkerställa driftsäkerhet och efterlevnad av Bokföringslagen krävs en robust strategi för backup och återställning.  
ADR-0023 (deployment/infrastruktur) och ADR-0038 (arkivering & revisionsspår) pekar på behov av dagliga backuper och retention.

## Beslut
- **Omfattning**  
  - Databaser: Postgres (långtidsminne, pluginstate), SQLite (korttidsminne, sessioner).  
  - Filer: uppladdningar (`/mnt/nfs/uploads/`), arkiv (`/mnt/nfs/archives/`), rapporter (`/mnt/nfs/reports/`).  
  - Konfigurationsfiler (appsettings, secrets) exkluderas från repo men kan ingå i backup.  

- **Frekvens & retention**  
  - Daglig backup av alla databaser och filkataloger.  
  - Retention: 7 dagar på varm lagring (`/mnt/nfs/backups/`).  
  - Äldre backuper flyttas till kall lagring (`/mnt/nfs/cold-archive/`).  

- **Automatisering**  
  - Backup körs som Quartz-jobb (`BackupSchedulerService`).  
  - Resultat loggas i `JobHistory` och skickas till systemansvarig.  
  - Misslyckade backuper → DLQ och notifiering via multi-channel.  

- **Restore**  
  - Testad återställning är obligatorisk (minst en gång per kvartal).  
  - Restore-rutiner dokumenteras i `BACKUP_RESTORE_GUIDE.md`.  
  - Endast systemansvarig kan initiera restore.  

- **Säkerhet**  
  - Backuper krypteras (AES-256) innan lagring.  
  - Checksumma beräknas och lagras för att verifiera integritet.  
  - Accesskontroller begränsar vem som kan hämta backupfiler.  

## Konsekvenser
+ Säkerställer att kritiska data kan återställas vid driftstörning eller datakorruption.  
+ Laguppfyllnad (7 års lagring enligt Bokföringslagen).  
+ Backupstatus blir synlig via WebChat och notifieringar.  
- Ökad lagringskostnad.  
- Kräver disciplin att regelbundet testa restore.
