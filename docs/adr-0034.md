# ADR-0034: Fakturaflöden i FortnoxPlugin (skapande, utskick, Peppol, EasyInvoice)

## Status
Accepted — 2025-09-11

## Kontext
User Case B (fakturering) och roadmap visar behovet av ett tydligt fakturaflöde i FortnoxPlugin.  
Det omfattar skapande, utskick och stöd för flera leveranssätt (Peppol, EasyInvoice, PDF via e-post).

## Beslut
- **Fakturaskapande**  
  - Fakturor skapas via FortnoxPlugin med API-anrop.  
  - Kunddata hämtas från Fortnox eller registreras vid behov.  
  - Artiklar och tjänster definieras i `InvoiceItemService`.  

- **Utskick**  
  - Primärt via Peppol när mottagaren stöds.  
  - Alternativt via EasyInvoice (PDF).  
  - Fallback: PDF skickad via e-post.  
  - Utskick loggas i `InvoiceLog` med idempotensnyckel.  

- **Arbetsflöde i WebChat**  
  1. Användare: *“Fakturera 10 timmar till RFLX AB”*.  
  2. Isa skapar fakturan i Fortnox.  
  3. Isa återkopplar: *“Faktura skapad, vill du att jag skickar den?”*.  
  4. Användare bekräftar.  
  5. Isa skickar fakturan enligt vald metod.  
  6. Bekräftelse med fakturanummer returneras.  

- **Arkivering**  
  - PDF-version av fakturan sparas i `/mnt/nfs/invoices/`.  
  - Metadata (kund, fakturanummer, totalbelopp) loggas i Postgres.  

- **Felhantering**  
  - Misslyckade utskick hamnar i DLQ för manuell hantering.  
  - Isa informerar användaren i WebChat och erbjuder nytt försök.  

## Konsekvenser
+ Enhetligt fakturaflöde oavsett utskicksmetod.  
+ Idempotenta anrop förhindrar dubbelregistrering.  
+ Spårbarhet via InvoiceLog och arkiverade PDF:er.  
- Fler kodvägar att testa (Peppol, EasyInvoice, e-post).  
- Kräver integration med flera externa tjänster.
