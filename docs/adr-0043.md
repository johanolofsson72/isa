# ADR-0043: Multi-tenant & Byråstöd

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent ska inte bara stödja ett bolag utan kunna användas av bokföringsbyråer med flera kunder.  
Varje klient behöver ha separata inställningar, plugin states, och åtkomstkontroller.  
Klientportalen (ADR-0021) och roller (ADR-0020) pekar på behovet av full multi-tenant-arkitektur.

## Beslut
- **Tenant-isolering**  
  - Alla data (verifikationer, bilagor, rapporter) taggas med `tenantId`.  
  - Datamodeller i Postgres har kolumnen `tenantId` som obligatoriskt fält.  
  - Plugins laddas per tenant (via `PluginState`).  

- **Byråstöd**  
  - Systemansvariga kan hantera flera tenants från samma instans.  
  - Ekonomiansvariga ser endast sitt eget bolag.  
  - Klientportalen visar enbart data för respektive kund.  

- **Plugin management per tenant**  
  - Plugins kan aktiveras/deaktiveras per kund.  
  - `PluginState` och `PluginMetadata` kopplas till `tenantId`.  

- **Authentication**  
  - OAuth/BankID används per tenant.  
  - Fortnox-integration konfigureras separat per kund.  

- **Deployment**  
  - Samma Swarm-kluster kör flera tenants parallellt.  
  - NFS-arkiv struktureras per tenant: `/mnt/nfs/<tenantId>/archives/`.  

## Konsekvenser
+ Möjliggör att en bokföringsbyrå kan hantera flera kunder i samma system.  
+ Tydlig isolering mellan olika bolag → GDPR-efterlevnad.  
+ Plugins blir flexibla och kan anpassas per kund.  
- Ökad komplexitet i datamodell och plugin lifecycle.  
- Kräver extra UI för att byta/administrera tenants i WebChat och klientportal.
