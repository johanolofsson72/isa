# ADR-0045: OCR & AI-dokumenttolkning

## Status
Accepted — 2025-09-11

## Kontext
ADR-0019 beskrev filhantering och dokumenttolkning på en övergripande nivå.  
Det behövs ett fördjupat beslut om hur OCR och AI ska kombineras i **DocumentInterpreterPlugin** för att hantera olika typer av ekonomiska dokument (kvitton, leverantörsfakturor, kundfakturor, avtal).

## Beslut
- **OCR-lager**  
  - Primärt: **Azure Document Intelligence** för hög precision och språkstöd (svenska/engelska).  
  - Sekundärt: **Tesseract OCR** som fallback vid API-fel eller offline-scenarier.  
  - OCR-resultat normaliseras innan AI-tolkning.  

- **AI-tolkning**  
  - LLM används för att klassificera dokumenttyp och extrahera strukturerad data.  
  - Prompt engineering säkerställer att output alltid följer ett definierat schema (`FinancialDocumentDto`).  
  - AI används särskilt för fritextfält (referenser, beskrivningar).  

- **Pipeline**  
  1. Dokument laddas upp via WebChat eller ingestion (Mail/Drive/Dropbox).  
  2. OCR körs → text extraheras.  
  3. AI-modell körs → dokumenttyp identifieras + fält extraheras.  
  4. Resultat skickas till `FortnoxPlugin` för bokföring och bilagelänkning.  
  5. Originalfil + OCR-text + AI-output arkiveras.  

- **Felhantering**  
  - Om OCR/AI är osäkert → dokument flaggas som “🟡 osäker” och skickas till manuell review.  
  - Alla misslyckanden loggas i `DocumentErrorLog`.  

- **Testning & träning**  
  - Unit- och integrationstester körs på en testsvit av kvitton och fakturor.  
  - AI-modellen förbättras över tid med *active learning* baserat på manuella korrigeringar.  

## Konsekvenser
+ Högre automatiseringsgrad i dokumenthantering.  
+ Hybridlösning (Azure + Tesseract + AI) ger både robusthet och flexibilitet.  
+ Spårbarhet tack vare arkivering av alla steg (original, OCR, AI-output).  
- API-kostnader för Azure Document Intelligence.  
- Kräver noggrann kontroll för att undvika hallucinationer i AI-output.
