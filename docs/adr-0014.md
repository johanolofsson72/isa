# ADR-0014: Notifieringar & Kommunikation

## Status
Accepted — 2025-09-11

## Kontext
AccountingAgent behöver kunna informera användare och kunder via flera olika kommunikationskanaler.  
Issues och roadmap beskriver stöd för:  
- E-post (MailPlugin, SMTP/Mailjet).  
- SMS (SmsPlugin via Twilio).  
- WhatsApp (WhatsAppPlugin via Twilio Business API).  
- Slack (SlackPlugin).  
- Microsoft Teams/Office 365 (MicrosoftOfficePlugin).  

Notifieringar måste vara **idempotenta** (inga dubbletter) och kunna styras via arbetsflöden (Quartz).

## Beslut
- **Plugins**:  
  - `MailPlugin` för e-post (SMTP, Mailjet).  
  - `SmsPlugin` för SMS (Twilio).  
  - `WhatsAppPlugin` för WhatsApp (Twilio Business API).  
  - `SlackPlugin` för Slack (app-manifest + OAuth).  
  - `MicrosoftOfficePlugin` för Teams/OneDrive.  

- **Arkitektur**:  
  - Alla notifieringar går via en central `NotificationService`.  
  - Idempotens nyckel (ex. `externalIdempotencyKey`) för att undvika dubbletter.  
  - Utskick loggas i `JobHistory` och `AuditLogService`.  

- **WebChat-integration**:  
  - Användaren kan i dialog be Isa: *“Skicka en påminnelse via SMS till kunden”*.  
  - Isa exekverar via NotificationService + rätt plugin.  
  - WebChat visar status: *“SMS skickat till +46…”*.  

- **Felhantering**:  
  - Retries med exponential backoff vid API-fel.  
  - Dead-letter queue om leverans misslyckas permanent.  

## Konsekvenser
+ Stöd för flera kommunikationskanaler → flexibilitet.  
+ Idempotens och loggning ger säkerhet och spårbarhet.  
+ Plugins kan enkelt utökas med fler kanaler (t.ex. Discord).  
- Beroende av externa tjänster (Twilio, Mailjet).  
- Kostnader för notifieringar kan öka vid hög trafik.
